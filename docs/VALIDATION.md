# 검증 기록

## YouTube 광고 건너뛰기 0.2.0 (2026-10-20)

- `npm run check`: 타입 검사, 69개 테스트(6개 파일), 빌드 통과. 기존 53개에 YouTube 엔진·경로·권한·설정 이전 15개와 팝업 독립 설정 1개를 추가했다.
- jsdom에서는 버튼 삽입, disabled/hidden/aria-disabled 해제, 숨겨진 카운트다운 컨테이너, 광고 재진입, 중복 억제, SPA 영상 전환, 전체/개별 OFF, 종료 후 이벤트 해제 및 비대상 버튼 제외를 검증했다.
- 실제 YouTube PC 웹의 광고에서 `button.ytp-skip-ad-button` 및 `#movie_player.ad-showing`을 관찰했다. 페이지 새로고침 직후 별도의 격리 실행 환경에서 **동일한 엔진과 YouTube 어댑터**를 실행해 자동 클릭 2회, 이후 광고 상태 해제와 스킵 버튼 제거, 본편 플레이어 복귀를 확인했다. 광고 두 개를 각각 추적한 기록이나 클릭 지연 측정은 아니다.
- 기존 Netflix 모의 브라우저 시나리오 13/13 통과. 이번 실행의 삽입/활성화→클릭은 0.40–1.20ms로 관찰했으며 실제 Netflix 응답 시간으로 일반화하지 않는다.
- 위 재생 검증은 인앱 브라우저에서 엔진을 직접 실행한 결과다. Chrome 확장 설치본의 manifest 주입·실제 chrome.storage·권한 승인·스토어 자동 업데이트를 검증한 것은 아니다. 테스트 탭은 종료해 임시 실행 코드를 정리했다.
- 실제 팝업 코드와 모의 localStorage에서 YouTube OFF → 새로고침 후 유지 및 Netflix 옵션 유지 확인. 팝업 크기 360×577.5px, footer 하단 561.5px로 확인했다. 스토어용 JPEG는 1280×800이며 실제 팝업을 표시한다.
- `npm run package`와 `unzip -t` 통과. ZIP 9,978 bytes, content.js 4,832 bytes, popup.js 1,934 bytes. 런타임 의존성·반복 타이머·외부 전송은 추가하지 않았다.

아직 확인하지 않은 범위: 설치본의 저장소·탭 간 설정 이벤트, 다른 광고 UI 실험군·언어·계정, Windows/Linux, 백그라운드·전체 화면, 기존 Netflix 실재생 재검증. YouTube 지원은 PC 웹 `/watch?v=…`에 한정하며 Shorts·외부 삽입 플레이어를 제외한다. 비공개 CSS 클래스가 바뀌면 새 관찰과 수정이 필요하다.

0.2.0의 스토어 업로드·심사 제출·배포는 아직 진행하지 않았다.

## 초기 구현 검증 (2026-10-05)

macOS, Node.js 26.8.1, npm 11.19.0에서 `npm run check`로 TypeScript strict 검사, 45개 Vitest 테스트(jsdom 및 게시 도구 테스트), esbuild 빌드를 확인했다. 2026-10-05 GitHub Actions의 Node.js 22/Ubuntu에서도 구현 커밋 `efb25bf`의 [검사와 빌드 산출물 업로드가 성공했다](https://github.com/ing2720/broskip/actions/runs/37299712474). 이는 Linux의 자동 테스트·빌드 검증이며 실제 브라우저 재생 검증은 아니다.

테스트는 버튼 삽입·활성화, 조상 숨김·CSS·화면 밖 상태, 중복 클릭 및 재생성, 재시청, browse→watch 진입, 회차 교체, 추천작·상시 다음 버튼 제외, 전체/종류별 OFF 및 복구를 포함한다. 관계없는 자막 변경에서 레이아웃을 재확인하지 않는 동작과 설정창의 저장 실패·초기 읽기 경합도 검증한다.

초기 45개에는 이전 게시 도구의 가짜 Git/CLI 테스트 6개가 포함되어 있었다. 브랜치 흐름 변경으로 해당 일회성 도구와 테스트는 제거했다. 초기 수치와 현재 테스트 수를 구분한다.

## 개발 흐름 정리 검증 (2026-10-13)

macOS / Node.js 26.8.1에서 `npm ci`, `npm run check`, `npm run package`를 실행했다. 타입 검사, 51개 테스트, 빌드 및 ZIP 무결성 검사가 통과했다. 현재 테스트는 엔진 24개, 다음 회차 11개, 팝업 4개, PR 브랜치 경로 12개로 구성된다.

실행 코드(`src/`, `public/`)는 기존 구현과 동일하다. 게시 도구·해당 모의 테스트를 제거하고, PR 경로 검사와 개발 문서를 새 흐름에 맞췄다. 빌드 결과는 content.js 4,088 bytes, popup.js 1,897 bytes이며 실행 시 외부 의존성은 없다. 이번 작업에서는 실제 Netflix 재생이나 Chrome 모의 화면을 다시 실행하지 않았다.

## 초기 실제 Chrome의 모의 DOM

`npm run dev`로 연 테스트 UI에서 **13/13** 시나리오 통과:

1. 활성 오프닝 버튼 삽입
2. 비활성 버튼 제외
3. 줄거리 버튼 활성화
4. 조상 숨김 제외
5. 숨김 해제
6. 같은 버튼 및 즉시 재생성 연타 방지
7. 추천작·상시 다음 버튼 제외
8. 전용 다음 회차 클릭
9. 회차 전환 뒤 감지 복구
10. 전체 OFF
11. 전체 ON 복구
12. 투명 요소 제외
13. 실제 CSS 전환 완료 후 감지

이 실행에서 삽입/활성화→클릭 측정 세 건은 **1.70ms, 1.10ms, 1.10ms**였다. DOM 변경 직전과 클릭 이벤트의 `performance.now()` 차이를 기록했다. 표본 세 건의 로컬 확인이며 평균 성능, 상한, Netflix 실서비스 지연 또는 다른 플랫폼 성능을 주장하지 않는다.

모의 브라우저 확인 이후 추가한 OFF 기간의 버튼 재사용 처리는 별도 자동 회귀 테스트로 확인했다.

설정창의 전체 OFF, 개별 줄거리 OFF, 새로고침 후 설정 유지와 하단 표시도 Chrome에서 확인했다. 미리보기는 localStorage 기반 모의 저장소이며 실제 Chrome 확장 저장소 검증을 대신하지 않는다.

## 패키지

`npm run package`로 `manifest.json`이 최상위에 있는 Chrome 웹스토어 제출 ZIP을 생성하고 `unzip -t`로 무결성을 확인한다. 실제 생성 ZIP의 SHA-256은 `artifacts/SHA256SUMS`에 기록한다. 실행 파일과 아이콘만 포함하며 소스·개발 의존성·모의 화면·인증 정보는 포함하지 않는다.

### 웹스토어 제출 준비 (2026-10-13)

macOS에서 `npm run check`의 타입 검사·53개 테스트·빌드가 통과했다. 기존 51개에 ZIP 루트 구조·중첩 아이콘 포함·dist 외부 파일 제외·동일 입력 재생성 및 manifest 누락 실패 검증 2개를 추가했다. 제출 ZIP 9,580 bytes의 무결성과 아이콘 16/32/48/128px, 홍보 이미지 440×280px, 설정 UI 캡처 1280×800px를 확인했다.

실행 JavaScript 크기는 content.js 4,088 bytes, popup.js 1,897 bytes로 동일하다. 설정창 캡처는 실제 팝업 코드를 모의 저장소로 실행한 로컬 화면이며 Netflix 재생 검증이 아니다. 스토어 업로드·심사·설치본 검증은 아직 진행하지 않았다.

## 사용자 실사용 보고

사용자는 설치한 확장으로 실제 Netflix 시청 중 자동 스킵을 잘 사용하고 있다고 보고했다. 이는 사용자 실사용 보고이며 아래 조건을 모두 재현한 통합 테스트 기록은 아니다. 이번 브랜치 정리 작업에서는 실제 재생을 새로 테스트하지 않았다.

## 조건별 검증이 추가로 필요한 것

- Chrome 확장 설치 상태의 `chrome.storage.local` 및 탭 간 설정 반영
- 실제 Netflix의 버튼 구조·자동 클릭 수용·마지막 회차 추천작·전체 화면
- 계정별/다국어 UI 및 Windows/Linux 실제 브라우저

초기 자동화 확인 당시에는 Netflix 로그인 이후 재생까지 확인하지 않았다. 위 사용자 실사용 보고와 별도로 조건별 재현 결과를 추가한다.

## 수동 통합 확인

개발 검증에서는 빌드한 `dist` 폴더를 Chrome에 로드하고 Netflix 탭을 새로고침한다. 게시 후에는 웹스토어 설치본으로도 같은 항목을 확인한다. 오프닝·줄거리·엔딩이 있는 일반 회차에서 각각 한 번만 클릭되는지, 다음 회차에서도 감지가 이어지는지 확인한다. 마지막 회차 뒤 추천작이 자동으로 재생되지 않는지도 확인한다. 전체/종류별 OFF와 다시 ON, 전체 화면, 탭 새로고침을 검증한다. 문제가 생기면 계정 정보나 영상 대신 버튼의 data-uia·표시·비활성 상태만 기록한다.
